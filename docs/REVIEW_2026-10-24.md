## Part 2: Could this be packaged and sold?

Short answer: **not as it is.** It is a working single-user personal system with one owner's identity, channels,
cloud accounts and hardware assumptions built in. The core idea (quote-verified talk cards merged into private
local notes) is sellable; the packaging work is substantial. Details below; nothing here is legal advice.

### 2.1 What a buyer must install today (from the code)

Laptop:
1. Node 22 + `npm ci --ignore-scripts` (tsx, TypeScript 7).
2. Git (merge and the page call `git` in `notes/`).
3. Ollama, with `gemma4:12b` (and optionally `gemma4:e4b`) and `embeddinggemma`. Ollama must be on
   `127.0.0.1:11434` (hard-coded in `llm.ts`, `embed.ts`, `web.ts`). Gemma 4 12B on CPU: minutes per typed answer
   (README); model download size not measured here.
4. Whisper base is downloaded on first voice use by transformers.js into `node_modules/@huggingface/transformers/.cache`.
5. A MongoDB Atlas connection string in `.env` (`MONGODB_URI`), and the Atlas data already filled by a server.
6. Windows only for the scheduled run (`deploy/morning-task.ps1`, Task Scheduler set up by hand).

Server (needed to produce any cards at all):
7. A DigitalOcean Droplet (Ubuntu 24.04, scripts assume root SSH, `/opt/lecture-gate`, 1 GiB RAM + 1 GB swap),
   Temporal CLI 1.9.1 dev server, systemd units, ufw, a public `CALLBACK_URL` on port 8080 for WebSub.
8. Keys: `DO_MODEL_ACCESS_KEY` (Gemma 4 31B + bge-m3 on DO serverless inference), `SERPAPI_API_KEY`, `MONGODB_URI`
   (Atlas with a vector index named `vec`; index creation is not scripted in the repo as far as I found **[not checked in depth]**),
   `WEBSUB_SECRET`, `CALLBACK_URL`; optional `SENTRY_DSN`, `BACKBOARD_API_KEY`.
9. Optional: `ELEBENT_API_KEY` (ElevenLabs) for demo voices/music; `GEMINI_API_KEY` only for model trials.

That is roughly 5–7 accounts and two machines for one user. Not a consumer install.

### 2.2 Hard-coded personal data and assumptions

- **Name**: "Ms Lee" in `src/lib/fillers.ts:33-35` and `src/web/index.html:582`.
- **Place / time**: default city (`fillers.ts:53`), greeting by `Europe/Berlin` hour (`fillers.ts:32`).
- **Channels**: 3 YouTube channel IDs with `since` dates in `src/lib/channel.ts` (incl. `@TechBridge-KR`).
- **Dates**: `FETCHED = 2026-10-20` in `channel.ts`, `web.ts`, `quick.ts` (age calculation of old videos).
- **Notes**: chat chips name the sample notes ("Agent Harness", "Hybrid search", "Code review with agents",
  `index.html:487-491`); `notes.sample/` is the owner's own writing.
- **Language**: Korean-narrated talks skipped; Korean words in the "tired" regex; English-only cards.
- **Voices**: ElevenLabs voice IDs "on this account" (`tts.ts:10-16`).
- **Infra**: Backboard assistant name `lecture-gate-rules`; Temporal at `localhost:7233`; DO endpoint fixed;
  model list fixed in `web.ts` (`MODELS`).
- **Data**: `data/` and `map/` hold collected YouTube titles, speakers and quotes (gitignored, so not in the repo).
- Tracked docs name the GitHub user and dev.to post (`docs/SUBMISSION_draft.md`), fine for a portfolio, not for a product.

### 2.3 Secrets handling

- `.env` is gitignored; only `.env.example` is tracked; no keys found in tracked files (searched for key-like patterns
  and IPs). **[checked]**
- Custom `.env` loader (`src/lib/env.ts`): no quoting, crashes if `.env` is missing, keys in plain text.
- `deploy/push.sh` copies the **whole laptop `.env`** to the server, so laptop-only keys (ElevenLabs, Gemini) also
  sit on the Droplet. Server `.env` is `chmod 600` and owned by a system user (good).
- `.env.example` incomplete (B5).
- For a product: per-user keys would need a settings UI / OS keychain, or the vendor would hold the keys server-side.

### 2.6 Minimum work for a sellable package (suggestions, not decided)

The cheapest viable shape is probably **"shared server, local client"**: the vendor runs one pipeline for a catalogue
of channels, and buyers install only the laptop part. Minimum list for that shape:

1. **Read-only card feed** instead of buyers holding an Atlas URI (a small HTTPS API or read-only Atlas user per buyer).
2. **Config instead of code**: name, city, timezone, channels/topics, models, port, voices in one settings file or a
   first-run wizard on the page; remove "Ms Lee", the default city, `FETCHED`, fixed chips, Korean regex.
3. **Installer / doctor**: check Node, Git, Ollama and the pulled models; `.env` optional; `notes --init`; schedule the
   morning run on Windows and macOS.
4. **No-server mode** (optional): a "bring your own SerpApi + Gemini/DO key" mode that runs transcript → card on the
   laptop for a handful of talks, so a single user can try it without a server.
5. **Clean leftovers**: B1–B6 and the table in 1.6.
6. **Tests** (README: none) for quote check, merge "nothing above the heading changes", quick-answer routing.
7. **Legal**: YouTube/SerpApi terms for redistributing transcripts and quotes; pass on Gemma Terms for EmbeddingGemma
   (or switch to an MIT/Apache embedding model); privacy notice for the Open-Meteo/HN/ElevenLabs calls.
8. **Hardware statement**: Gemma 4 12B on CPU takes minutes per typed answer; buyers need to know the RAM/GPU needed
   (not measured here).

Effort estimates for these items: **not estimated** in this review.
